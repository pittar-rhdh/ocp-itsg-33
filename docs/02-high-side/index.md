# Phase 2 — High-Side Setup

[← Back to main](../index.md)

> **Examples only — not validated.** The commands and configuration in this phase are examples.
> They have not been run against a real Red Hat subscription, air-gapped environment, or
> cluster. Test and adapt them before use. See [Validation status](../reference/validation-status.md).

Prepare the air-gapped environment: accept the transfer, build and harden the registry host,
install the mirror registry, populate it, and produce everything the cluster install needs.

| | |
|---|---|
| **Where** | High side: registry host in the MRZ |
| **Inputs** | A Phase 1 [transfer package](../01-mirroring/packaging-and-transfer.md#package-layout); the transfer public key (delivered out of band); departmental DNS, NTP, PKI, and Git |
| **Outputs** | Hardened, populated mirror registry with departmental TLS; pull-only cluster credentials; generated cluster resources (IDMS, ITMS, catalogs, release signatures, update graph); FIPS-capable `openshift-install-fips` pinned to the release digest; this repository on departmental Git; the import log |
| **Hands off to** | [Phase 3 — Cluster install](../03-cluster-install/index.md) |
| **Decisions** | AD-10, AD-12, AD-15, AD-18, AD-21 ([Architecture decisions](../00-architecture/architecture-decisions.md)) |
| **Key controls** | AC-2, AC-3, AC-6, CM-6, CM-7, CM-11, IA-5, SC-8, SC-12, SC-17, SI-7, AU-2 |
| **Versions** | OpenShift 4.22.18, mirror registry 2.0.9, and other pins: [Versions and pinned content](../reference/versions.md) |

## Workflow

```text
 media ──> accept transfer ──────────────> publish repository ──> departmental Git
           (gpg, sha256sum, order check,
            import log, unpack tools)
                 │
                 v
 registry host checks ──> install mirror registry ──> harden ──> robots and permissions
 (OS, FIPS, DNS, NTP,      (rootless, departmental     (no anonymous,  (org "mirror",
  storage, certificate)     certificate)                no sign-up, TLS) importer, cluster_pull)
                                                                         │
                 disk to mirror  <───────────────────────────────────────┘
                 (oc-mirror --v2, cluster-resources/<ID>)
                       │
                 extract installer ──> Phase 3
                 (openshift-install-fips, release.env)
```

Host build, registry installation, hardening, and access setup happen once (and again for
upgrades or certificate rotation). Accepting, importing, and publishing happen for every transfer.

Conventions on these pages: the registry is `registry.example.gc.ca:8443`, all content is in
the organization `mirror`, the registry runs as the account `quay`, registry data is under
`/data/quay`, and everything else (transfers, oc-mirror workspace and cache, cluster resources,
tools, installer) is under `/data/ocp`. Replace `example.gc.ca` values and `<placeholders>` with
your own.

## How this phase supports ITSG-33

| Control | How |
|---|---|
| SI-7, SA-12 Integrity and supply chain | Every transfer is verified on the media and again after copying; tools come only from verified transfers; the installer is pinned to a release digest with a mirrored signature |
| CM-3 Change control | Transfers are imported in build order and recorded in an import log; Git is fast-forwarded only from reviewed low-side history |
| AC-2, AC-3, AC-6 Accounts and least privilege | No self-registration or anonymous pulls; one break-glass administrator; separate push-only and pull-only robot accounts; the cluster never receives push credentials |
| IA-5 Authenticator management | Robot tokens are generated by the registry, stored mode `0600`, checked, and rotated on a schedule |
| SC-8, SC-12, SC-13, SC-17 Transport and PKI | Departmental certificate checked for name, chain, key size, algorithm, and expiry; TLS 1.2/1.3 only; host in FIPS mode |
| CM-6, CM-7 Configuration and least functionality | Hardened registry settings recorded and re-checked after upgrades and on a schedule; repository mirroring disabled |
| AU-2, AU-12 Audit | Host auditd and the registry's journald logs forwarded to the SIEM; hardening and import records kept |
